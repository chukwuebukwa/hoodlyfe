# NOCK0 Level Editor

## Purpose

The level editor is the authoring surface for the complete district, not a screenshot
annotator. It loads the same map, collision, road classification, lane graph, junctions,
roadblocks, and default spawn that the game consumes. Edits are represented by a versioned
editor document and exported through explicit adapters into the existing runtime files.

Run the normal development stack and open:

```text
http://127.0.0.1:5173/editor
```

The editor uses React for tool state, panels, validation, and persistence. Canvas2D owns the
high-frequency viewport, visible-cell rendering, hit testing, brush strokes, and direct
manipulation. This boundary prevents a pointer move over a 65,536-cell map from causing a
React render for every cell.

## Source Ownership

| Editor data | Runtime file | Notes |
| --- | --- | --- |
| Base map image | `district-preview.png` | Read-only visual reference; regenerated by the converter. |
| Collision cells | `district-map.json` / `collisions` | `0` is open; nonzero is blocked. |
| Road cells | `district-map.json` / `roads` | Nonzero marks a road-classified tile. |
| Lane corridors | `district-lanes.json` | Directed lanes are compiled from authored centerlines. |
| Junctions | `district-lanes.json` | Connect corridor IDs and own allowed turns. |
| Police roadblocks | `district-lanes.json` | Own blocked edge IDs, vehicle poses, stinger, and officer pose. |
| Default player spawn | `district-map.metadata.json` | The first enabled player spawn is emitted. |

The editor preserves the complete Tiled map document and only replaces the `collisions` and
`roads` layer data. Ground tiles, tilesets, properties, and converter metadata are left
unchanged. Metadata counts are recalculated when a game bundle is exported.

The editor document already models pedestrian, traffic, police, and mission spawn kinds so
those tools do not require a schema break later. The current runtime has one authored spawn
contract, `metadata.spawn`, so only the first enabled player spawn is emitted into runtime
files today. Keep other spawn kinds in an exported `.level.json` project until their domain
catalog adapters are added.

## Workspace

The editor has four stable areas:

1. The top toolbar owns history, viewport controls, validation, import, and export.
2. The left panel owns tools, layer visibility, snapping, brush size, and the searchable
   object tree.
3. The center canvas owns the full map and direct manipulation.
4. The right inspector owns exact values for the current selection.

The validation drawer sits above the status bar. Selecting an issue selects its object and
frames the relevant world position.

### Navigation

- Mouse wheel: zoom around the cursor.
- Middle drag, Space drag, or Pan tool: move the viewport.
- `F`: fit the complete `16384 x 16384` world.
- Toolbar square: use one screen pixel per world pixel.
- Toolbar plus/minus: change zoom around the viewport center.

### Tools

| Tool | Shortcut | Behavior |
| --- | --- | --- |
| Select | `V` | Select and drag spawns, junctions, roadblocks, corridors, or individual corridor points. |
| Pan | `H` | Drag the viewport without changing content. |
| Collision paint/erase | `B` / `Shift+B` | Apply a bounded tile brush to the collision layer. |
| Road paint/erase | `R` / `Shift+R` | Apply a bounded tile brush to road classification. |
| Corridor | `C` | Click vertices; press Enter or double-click to finish; Escape cancels. |
| Junction | `J` | Place a junction and attach up to four nearby corridors as an initial guess. |
| Spawn | `S` | Place the selected spawn kind. |
| Roadblock | `K` | Place a roadblock template, then configure compiled edge IDs in the inspector. |

All point entities use the selected snap interval. Collision and road brushes always operate
on tile cells. A brush stroke is one history command even if it changes hundreds of cells.
Entity drags are also one command. History is capped at 100 commands and cell history stores
compact index patches rather than complete map copies.

## Validation

Validation runs continuously and checks:

- tile-layer lengths against map dimensions;
- at least one enabled player spawn;
- duplicate IDs;
- bounds and collision at spawn positions;
- corridor point count, speed, lane count, map bounds, zero-length segments, and road cells;
- junction corridor references and spatial attachment;
- roadblock bounds, vehicle poses, and blocked-edge ownership.

Errors block a normal apply workflow. The browser permits an intentional export after a
confirmation, while the CLI rejects errors unless `--force` is supplied. `--force` is for
recovery work, not ordinary authoring.

## Save And Apply

The editor autosaves the current versioned document to IndexedDB after 900 ms of inactivity.
Drafts are keyed by district ID and map fingerprint, so a draft from a different source map,
tile size, or origin is not restored accidentally.

Use the gamepad command to create **Play Draft**. It validates and snapshots the exact current
in-memory document into an immutable, content-addressed IndexedDB revision, then opens the
district explorer with that revision. The local preview currently applies draft collision and the
enabled player spawn while streaming the existing Three.js presentation chunks. It does not apply
files to the repository or join an authoritative multiplayer room. The status bar retains a link
to the last revision if the browser blocks the new tab.

Asset route IDs and authored world IDs are distinct. For example, the preview route uses
`district=bil`, while the revision retains `industrial-district`. Revision IDs are looked up by
their content hash and validated against the selected asset source before the preview starts.

Use **Project** to download the editable document. Use **Game bundle** to download an
artifact bundle containing the editor document and the three runtime files.

Check a bundle without writing:

```bash
npm run level:apply -- ~/Downloads/industrial-district.game-bundle.json --check
```

Apply it atomically per file:

```bash
npm run level:apply -- ~/Downloads/industrial-district.game-bundle.json
npm run map:validate
npm test
npm run build
```

The apply command accepts only the fixed runtime paths in the versioned bundle, validates the
document and map contract first, writes temporary sibling files, then renames them over the
live files. It cannot write an arbitrary bundle path into the repository.

## Coordinates And Streaming

Editor coordinates are active world pixels. The complete map is `256 x 256` tiles at `64`
pixels per tile. The base preview is a lower-resolution image stretched over those exact world
bounds. The game still streams Three.js presentation chunks by camera interest; editor changes
to collision and roads remain resident because those grids are small and simulation-critical.

Do not manually subtract or add the old reference-frame offset in the editor. The map expansion
pipeline owns source-origin rebasing. If a future editor adapter targets TypeScript catalogs
that use `districtPoint` or `districtBounds`, its export adapter must convert active coordinates
back through that reference contract instead of embedding an offset.

## Adding Interiors And New Domains

Add a new domain in four pieces:

1. Add a browser-safe type to `src/tools/level-editor/level-document.ts`.
2. Load the current source in `assembleLevelDocument` and emit it in `createArtifactBundle`.
3. Add domain validation to `level-validation.ts`.
4. Add a layer renderer/hit test plus a focused React inspector.

Interiors should enter as a separate authored layer with room bounds, doors, entry/exit
anchors, obstacles, service anchors, and roof-occluder references. Do not paste the current
interior author into the map canvas. Reuse its catalog adapter and migrate its local draft only
after the editor document owns the complete round-trip contract.

The same pattern applies to signals, street lights, population zones, mission anchors,
services, parking, and property entrances. Each domain keeps one runtime owner and one editor
adapter. The level editor coordinates them; it does not absorb their simulation logic.

## QA Checklist

- Fit view shows the entire source map without a blank canvas.
- Collision and road overlays line up with the base preview at fit and close zoom.
- Wheel zoom remains centered under the cursor.
- A multi-cell brush stroke undoes and redoes as one operation.
- Dragging a corridor point does not move the complete corridor.
- Renaming a corridor updates junction references.
- Deleting a corridor removes its junction references.
- Validation issue selection frames the correct object.
- Reload restores the latest compatible IndexedDB draft.
- Play Draft opens in a fresh tab, displays its revision ID, and uses the authored spawn and
  collision grid without browser errors.
- Project and bundle imports reject incompatible dimensions.
- Bundle `--check`, `map:validate`, tests, and production build pass before committing data.
- Desktop and mobile widths expose the canvas without panel or toolbar overlap.

## Prioritized Roadmap

The editor foundation intentionally stops at domains with a complete runtime round trip. The
next production milestones, in order, are:

1. District manifests, a district browser, and streaming/chunk boundary visualization.
2. A simulation mode for traffic, pedestrian, police, and spawn diagnostics without joining
   the multiplayer room.
3. A reusable world-object palette for lights, signals, pickups, services, mission anchors,
   interior doors, parking, and property entrances.
4. Compiled lane-edge and turn previews, traffic signal phases, one-way rules, and topology
   diagnostics for dead ends and disconnected subgraphs.
5. A deliberate art-authoring bridge to Tiled or Blender. The flattened base preview remains
   reference-only until that bridge can preserve source geometry and texture ownership.
6. Review tooling: document diffs, bookmarks, issue suppression with reasons, and before/after
   overlays.

Simulation and runtime ownership stay outside the editor. These tools visualize, validate,
and export authored inputs; they must not become a second implementation of game AI.

## Local District Packages

The editor can open multiple converted GTA2 districts without replacing the active multiplayer map.

```bash
npm run district:export -- wil 256
```

This writes a local, Git-ignored package to `public/assets/districts/wil/` containing the full
map, collision and road grids, preview image, Three.js atlas, surface grid, and streamed geometry
chunks. Use `ste` in place of `wil` to convert that district.

After export:

1. Open `/editor?district=wil` to inspect or edit the whole map.
2. Use the gamepad button or open `/explore?district=wil` for a local streamed walk preview.
3. Move with WASD, arrow keys, or the mobile direction controls.

Optional districts start with an empty lane graph until lanes are authored in the editor. The
apply-ready **Game bundle** command remains disabled outside BIL because the multiplayer server,
interiors, services, missions, and population systems are still bound to the active runtime
district. The editable project export remains available for every district.

Converted source-derived packages are intentionally excluded from Git. Commit the reusable
catalog, tools, and authored original data rather than the generated GTA2 assets.
