## 01:40 - Character Compiler Prototype and Rejected Paint-Over Direction

### Goal

- Build a standalone character-production tool that compiles one appearance recipe into aligned idle, walk, melee, hit, fall, vehicle-entry, carjacking, and death sheets for the canonical Three renderer.
- Replace one-off runtime sprite edits with versioned animation contracts, data-driven parts, compatible body families, semantic material channels, and bounded compiled-texture caching.

### Implemented Prototype

- Added the standalone Character Lab at `/creator.html` with animation/frame inspection, part and material controls, randomize/reset, local recipe storage, and JSON/walk/action exports.
- Added a versioned character animation manifest, part catalog, compiler, material masks, authored-layer composition hook, semantic action selection, and a 96-appearance Three texture cache.
- Removed the old in-game creator modal and routed Three player walk/action source loading through the shared character manifest instead of hardcoded asset paths.
- Added an AI-authored 3x3 idle/walk source atlas and normalized its dimensions and scale against the action atlas.
- Removed `drawAppearanceStyleDetails` from the new compiler path so its crude rectangle-based hair, hat, jacket, pants, and shoe stand-ins no longer execute there.
- Bumped the character asset contract to version 3 and cache-busted the new walk/action sources and masks.

### What Failed

- The visual result was rejected. The idle/walk output still read as a paint-over rather than a designed modular character: an oversized recolored hair mass, coarse top/pants/shoe blocks, incorrectly classified glove/arm pixels, and fake width scaling for the un-authored `broad` body.
- Removing the rectangle painter did not solve the underlying problem because coarse material masks still flooded regions of a single finished sprite with arbitrary colors. This is not equivalent to authored body, hair, shirt, pants, shoe, and accessory layers.
- Part controls continued to advertise hairstyles, clothing, headwear, and body variants that had no authored per-frame silhouettes. The metadata and compositor extension points existed, but the displayed content did not honestly satisfy those contracts.
- Technical correctness was mistaken for visual completion. The creator loaded and animated without browser errors, but that did not make the produced character acceptable.
- The attempted AI walk atlas was more internally consistent than the legacy GTA2 base, but its top-down proportions and material segmentation still did not match the required art direction. It remains a prototype asset, not approved production art.

### QA Results and Blockers

- The focused character manifest, material-channel, cache-key, and PNG-dimension suite passed `6/6`.
- Browser QA confirmed the standalone creator and canonical Three renderer loaded nonblank with no fresh console errors. Idle, walk, and melee clips switched correctly and the walk/action size pop was reduced.
- Full repository tests reached `226/227`. The failing existing long multiplayer integration scenario reported `Melee participants must remain alive (player=false/0, npc=true/60)`; this failure was outside the character compiler slice.
- Repository TypeScript and production build were blocked by an unrelated active change in `server/game/debug/debug-snapshot-controller.ts`: `TS2366`, function lacks an ending return statement. That shared work was not modified in this side task.
- No character milestone commit was created. The creator, compiler, documentation, tests, and generated assets remain part of the dirty working tree alongside unrelated active changes.

### Universal LPC Evaluation Started

- Began evaluating the Universal LPC Spritesheet Character Generator as a replacement reference for the failed paint-over approach.
- Confirmed its useful production patterns: synchronized transparent layers, metadata-driven categories and z-order, body compatibility, per-animation item coverage, palette definitions, JSON import/export, attribution export, split-sheet export, and a large existing clothing library.
- Confirmed important constraints: the generator code is GPL-3.0; individual art has mixed CC0, CC-BY, OGA-BY, CC-BY-SA, and GPL terms; selected authors and licenses must be tracked and exposed in game credits, and derivative/share-alike obligations vary by asset.
- LPC's standard 64x64 four-direction RPG perspective and animation layout do not directly match NOCK0's rotating top-down GTA presentation or current 72x72 semantic atlases. Its architecture is highly relevant, but adopting its art unchanged would produce a visible perspective mismatch and require renderer/animation conversion work.
- No LPC source, generator code, or art was copied into NOCK0 during this evaluation. The deeper adopt/adapt/reject decision was moved to the main task.

### Required Next Decision

- Stop extending mask-based paint-over customization.
- Decide in the main task whether to: use LPC as architecture only and author a NOCK0-specific top-down layer library; fork/convert a license-filtered LPC subset; or adopt LPC's visual perspective and replace the current character presentation contract.
- Whichever direction is selected, expose only genuinely authored options in the creator. A selectable item must provide aligned frames for every required clip, explicit layer order and occlusion, body compatibility, palette ramps or authored colors, and attribution metadata where required.
