# Development Log - 2026-07-18

## 02:08 CST - Stable Police Pursuit Tactics

- Re-audited pinned re3/reVC pursuit-slot registration, release, replacement, wanted
  limits, layered autopilot state, and authored roadblock ownership. The transferable
  production pattern is explicit finite assignment plus separate tactical intent,
  navigation, movement, and outcomes; neither source provides a reusable multiplayer
  squad-role planner.
- Added an original server-only `PursuitCoordinator`. It consumes the existing G1 response
  leases and projects stable primary, contain-left/right, support-left/right, and
  intercept-left/right responsibilities without allocating population or moving actors.
- Roles now persist for the life of the underlying response lease. Distance changes no
  longer reshuffle the group every tick; a vacated primary role promotes one deterministic
  replacement by assignment age, distance, and stable unit ID.
- Split tactical movement goals from authoritative aim facts for police pedestrians.
  Containment officers navigate to lateral positions and only the primary can initiate the
  existing point-blank melee behavior.
- Added role-relative cruiser destination policy. Secondary units intercept or contain and
  cannot inherit primary heat-3 ramming; lost units still search private last-known facts.
- Extended opt-in debug protocol, snapshots, panel summaries, and Three overlays with
  copied tactical role/phase/goal records. Unresolved observe records are not rendered as
  invalid world lines.
- Recorded the clean-room behavior and multiplayer boundary in
  `POLICE_PURSUIT_TACTICS_RESEARCH.md` and ADR 0019. Updated the architecture map and
  implementation roadmap. Arrest outcomes, force policy, officer exits, roadblocks, and
  stingers remain explicit later G3 slices.
- Kept the multiplayer simulation boundary frozen. No prediction, reconciliation,
  interpolation, combat rewind, AOI, interaction-island selection/replay, rollout, or
  shared movement/contact implementation changed.

## 03:16 CST - Authoritative Police Arrest and Custody

- Audited arrest entry, contact continuation, busted-state ownership, input suppression,
  and custody consequences in the pinned re3 and reVC sources. Both games separate an
  officer-owned arrest interaction from a player-lifecycle-owned terminal busted outcome;
  exact code and tuning remain reference-only.
- Added a pure police force policy that distinguishes primary-officer arrest contact,
  close-range resistance, visible ranged threat, and hold behavior. Secondary tactical
  roles cannot initiate custody, and arrested players cannot receive additional force.
- Added a modular `PoliceArrestController`. It owns one officer/suspect contact lease,
  revalidates authority, line of sight, space, life state, and separation every server tick,
  suppresses player input, records the officer's arrest tactic, and publishes typed start
  and cancellation events without owning economy or general lifecycle state.
- Added a separate `CustodyOutcomeController` and lifecycle completion path. A completed
  arrest confiscates weapons, clears wanted/combat/vehicle state, applies an idempotent
  bounded custody fee, chooses a collision-safe street release point, grants brief spawn
  protection, and publishes one typed busted event.
- Integrated the force decision with pedestrian perception/intent rather than adding the
  behavior to `DistrictRoom`. The room only composes controllers and adapters. Added ADR
  0020, the source audit in `POLICE_ARREST_FORCE_RESEARCH.md`, ownership documentation,
  and completed the G3b roadmap checklist.
- Added opt-in F3 custody diagnostics, copied debug snapshots, panel projection, and a
  Three overlay line between an active arresting officer and suspect. The complete arrest
  lifecycle and economic outcome are deterministic-testable without advancing global time.
- Preserved the multiplayer boundary: custody is server-authoritative and never replayed.
  No files under `shared/simulation`, `server/game/network`, or `src/game/netcode` changed.
