## 21:15 AST - On-foot reconciliation snapback fix

- Traced frequent local walking snapback to two regressions in the restored saved-input
  controller rather than collision geometry or the shared 60 Hz simulation step.
- The authoritative server intentionally holds the latest applied movement while its
  input queue is briefly empty. Multiple state patches can therefore move the server
  pose while carrying the same acknowledged input sequence.
- Stopped treating those same-acknowledgement patches as new reconciliation baselines.
  Reconciliation now runs only when acknowledgement advances, matching the proven
  behavior of the previous saved-input implementation.
- Rebuilt every surviving pending input snapshot during rewind/replay. Later
  acknowledgements now compare against the corrected replay timeline instead of stale
  pre-correction positions.
- Added regressions for repeated held movement with an unchanged acknowledgement and
  consecutive acknowledgements after a corrected replay.
- Applied the same correction to driven-vehicle prediction, which shares the sequenced
  held-input transport contract, and added equivalent vehicle regressions.
